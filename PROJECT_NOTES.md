# Заметки о развитии thesis

## План пользователя

1. Исправить оставшиеся недочёты системы.
2. Добавить обучение на удалённом GPU-сервере через SSH.
3. Добавить другие модели для сравнительных экспериментов.

## Сохранённое предложение о конфиденциальности SSH

Пользователь попросил сохранить ответ для возможного будущего использования.
Это предложение архитектуры, а не разрешение подключаться к серверу.

- Программа вызывает системные OpenSSH и rsync; приватный ключ не читает.
- Пользователь самостоятельно настраивает SSH, устанавливает публичный ключ на сервер, загружает приватный ключ в ssh-agent и вводит пароль в своём терминале.
- В конфигурации проекта сохраняются только псевдоним сервера (например, thesis-gpu) и удалённая рабочая папка.
- Первое подключение и проверку отпечатка сервера выполняет пользователь.
- ForwardAgent no: агент не пересылается на удалённый сервер.
- SSH-agent не выдаёт вызывающей программе приватный ключ, но доступ к его сокету позволяет использовать авторизацию. Это не равнозначно запрету доступа к серверу.
- Предложен вариант максимального разделения: агент разработки реализует код и проверяет его с имитацией SSH; реальные подключения и запуск обучения выполняет пользователь из собственного терминала, передавая только логи и результаты.
- Чтобы исключить чтение ключа агентом разработки, доступ к ключевым файлам ограничивают на уровне окружения/разрешений. Хранение вне проекта само по себе не гарантирует недоступность.
- Не запрашивать и не включать в проект приватный ключ или его пароль.

Источники исходного ответа: https://man.openbsd.org/ssh-agent.1 и https://www.openbsd.org/openssh/agent-restrict.html
